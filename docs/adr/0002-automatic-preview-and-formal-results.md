# 自动预览与人工确认的正式结果

焦斑分析工作区在打开受支持图像后，使用版本化分析档案自动完成预处理、背景样本选择、主焦斑候选定位和分析区域（ROI）提议，并立即产生不可导出的预览结果；用户不再逐步确认输入、标定、预处理和请求快照，只在最后通过一次操作确认当前 ROI 与“按相对强度码值测量”的语义并生成正式结果。自动候选一旦呈现便不得为改善结果而静默改变，用户修改 ROI、空间标定或分析参数后，旧正式结果保留但进入“需要重新计算”状态，新计算生成新的分析记录。

这一决定以零配置可用性换取“预览结果”和“正式结果”的明确分层：自动化负责给出可检查的初始状态，人工确认仍保留测量责任边界。正式结果表示配置已经复核，不表示测量有效；只要分析产生结构化记录，即使部分或全部指标无效，也可以生成显著标注无效状态和全部原因的测量报告。解码失败、无效 ROI 或没有产生结构化分析记录的流程失败仍只能导出诊断，不能伪装成正常测量报告。

本决定扩展 ADR-0001 中面向单张图像、显式确认后运行的 MVP 工作区交互，但不改变其模块边界：Python 分析核心仍是测量语义的唯一实现，WPF 客户端仍通过版本化 worker interface 调用核心，显示设置仍不得改变测量数据。工作区可以同时管理多张输入图像，但每张图像的草稿、预览结果、正式分析记录、测量有效性和导出状态保持独立；批量能力不引入跨图像统计或新的批次测量语义。

## 契约身份与历史边界

本 ADR 的产品决策由 `workflow-contract-v1` 承载，并由 `workflow-verification-contract-v1` 规定验证证据。前者只定义自动预览、ROI 草稿、最终确认、正式结果、需要重新计算和多图片工作项；后者只定义这些外部行为如何通过 seam 和人工验收得到证据。二者都不重新定义 FWHM、D4σ、EE、集中度、质量状态、解析 oracle、数值容差或 profile 验证状态。

本 ADR 替代 Issue #6 的首次 ROI 固定全图、逐项确认后计算和单图产品流程条款，替代 Issue #9 中仅适用于旧产品流程的“所有指标必须在用户确认后才开始”的界面解释，并替代 Issue #66 的显式配置确认、单图和旧报告门控假设。Issue #6/#9 的科学计算域、质量门控、确定性、历史记录和真实图像不等于物理真值的边界继续有效；ADR-0001 的 WPF/worker 边界也继续有效。

历史 `AnalysisRecord` 按其记录的契约、profile、算法和导出版本解释。实现不得使用 `workflow-contract-v1` 重新判定或静默重算旧记录；工作流或科学语义发生不兼容变化时，必须产生新的版本和新的 record ID。
